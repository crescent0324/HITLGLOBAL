# 2026-10-31 程式審查與修正

範圍：`care_console/` 的院內權限與資料層，以及 `care_console/core/` 的生成與送出控制。論文版本 `crescent0324/HITL` 未修改。

審查方式是兩路獨立程式審查，每個問題先寫重現程式確認，再修正並補測試。另以 Chromium 實際操作五種角色，視窗寬度 1440、820、390；也走完一次完整流程：家屬訊息、轉人工、接手、回覆、交班、接班、結案。

## 已修正

| 問題 | 影響 | 修正 |
| --- | --- | --- |
| 依舊畫面也能結案或回覆。高風險新訊息會併入同一案件，案件編號不變，所以舊畫面仍可結案 | 人工處理被過時的請求解除，新的警訊沒有人看就從待辦消失 | 詳細資料回傳 `seen_message_id`，前端在回覆與結案時送回；伺服器比對最新訊息，不符回 409 |
| 撤銷接手護理師的住民權限後，案件仍掛在他名下 | 有權的人無法接手、回覆或結案，家屬卻持續收到「由院內工作人員處理」 | 撤銷時將該員的案件改回待接手，取消其交班與生成工作，並留下 `owner_access_revoked` 紀錄 |
| 登出後，複製的工作階段 cookie 仍可使用最多 1 小時 | 共用電腦上的 cookie 可被沿用 | 新增伺服器端 `web_sessions`；登出即失效，舊 cookie 一律拒絕 |
| 照服員手動回報可指定任意 `source_record_id` | 可佔用院內匯入要用的識別碼，使整批匯入失敗 | 照服員回報一律由伺服器產生 `MANUAL-` 識別碼；匯入拒絕 `MANUAL-` 開頭；衝突錯誤標出列號 |
| 生成工作排隊或執行超過 10 分鐘，被靜默取消 | 使用者被告知「完成後會另送訊息」卻再也沒收到，工作人員也看不到 | 逾時改記為失敗：開啟人工案件、留紀錄，並通知使用者已轉人工確認 |
| 待審草稿超過 10 分鐘後無法核准也無法退回，卻仍顯示為可審閱 | 畫面誤導 | 背景工作將逾時草稿標為已取消並記錄原因；核准時若已逾時，直接拒絕並說明 |
| LINE 傳送遇到 `http.client` 協定錯誤（如 `IncompleteRead`）時例外外漏，工作卡在送出中 | 送出結果不明卻看似仍在處理 | 歸類為送出結果不確定 |
| 對家屬的回覆仍寫「研究操作人員」、「研究展示」 | 不符護理之家使用情境 | 改為「院內工作人員」；「本帳號沒有醫療人員值班」改為「本帳號不保證即時有人回覆」，緊急提醒不變 |

## 驗證

- 後端 103 項測試通過：原有 94 項，新增 9 項回歸測試，涵蓋上表 7 項程式問題。
- 兩路審查的重現程式在修正後重跑，問題均不再出現。
- 隨機訊息壓力測試約 960 則，無例外，也沒有違反人工處理規則。
- 瀏覽器實測：舊視窗結案會顯示「此對話有新訊息尚未查看」，更新後可看到高風險訊息。
- 新增 `.github/workflows/tests.yml`，每次推送與 PR 自動執行後端與前端測試。本輪環境無法安裝 jsdom，前端 25 項測試改由 GitHub Actions 執行。

## 介面變更

`POST /api/residents/<rid>/case/reply` 與 `.../resolve` 新增必填欄位 `seen_message_id`，值取自 `GET /api/residents/<rid>` 回傳的 `case.seen_message_id`。現有網頁已更新；自行呼叫 API 的腳本需一併調整。

升級後，既有的登入工作階段需要重新登入一次。

## 仍待處理（已確認風險較低或尚未重現）

- 人工回覆與核准的 API 會忽略核心回傳的送出狀態，一律回應成功。目前只允許離線模擬傳送，所以不會發生；接上真實 LINE 前必須修正。
- 部分多步驟寫入不在同一交易內，例如訊息寫入後才記錄作者，程式中斷時可能缺少作者紀錄。
- 雙資料庫啟動快照依序複製，只有在沒有其他程序寫入時才一致。
