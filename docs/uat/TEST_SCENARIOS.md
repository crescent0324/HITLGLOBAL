# 現場任務腳本 U01～U20

沿用 [原U編號及定義](../institution-workflow/USER_ACCEPTANCE_SCENARIOS.md)，不另編新任務。U01～U08用現有介面，U09～U20本輪一律紙卡（含原規格可選系統故障的U19）。每項預期結果供觀察者判讀，開始前只朗讀目的、前提及參與者操作，不先念答案。

每場使用QUICK_START全新資料夾。U01～U05連續使用R001同一個family對話及程式產生的case_id；U06用R003院內對話；U07用R001另一聯絡身分；U08回到已結案R001並選已結案／全部篩選。不要重跑展示程式來替受訪者完成案件。

固定虛構文字：M1「虛構：請協助安排家屬聯繫，轉人工」；M2「虛構：原先聯繫安排有變更，請重新確認」；進度P：已處理「虛構：已確認聯繫需求」、下一步「虛構：下一班確認安排後回覆」、待確認「虛構：尚待確認時間」。資料源、家屬及人工回覆全在本機。錯誤、提示、初始狀態不符都依MEASUREMENT保留，不悄悄清空後重試。

## U01～U08 系統操作

### U01 建立與接手

目的：讓家屬詢問形成待辦，辨識接手前後責任並保存下一步。

角色：護理師nurse。初始：全新場，R001沒有人工案件；首次首頁訊息待辦應為空。

1. 登入後先查看首頁「訊息待辦」。開R001，選服務對話與回覆對象的家屬體驗身分。
2. 進「服務對話」→展開「流程測試（本機）」→確認來源已自動顯示「LINE 傳入訊息模擬」及family家屬身分→送出M1。來源與身分由上方對話決定，鎖定時不需操作它們。
3. 關閉住民視窗，查看首頁新增待辦，說出目前誰負責；由「查看並接手」開同一案件。
4. 進「人工處理」按「接手此案件」。記case_id，填P後按「保存進度」，讀回已保存內容。

觀察者預期：待接手時沒有責任ID；接手後為nurse，P保存可讀回。待辦出現及系統固定待接手通知均不代表家屬已讀或照護完成；此任務不展示一般服務摘要。

### U08 撤權後不可存取

目的：驗證既有工作階段在撤權後不恢復舊內容。

角色：主持人admin＋head_nurse。初始：R001已結案；head_nurse可先以已結案／全部讀歷程，記case_id。

1. 保留護理長已開的歷程。主持人用獨立設定檔或登出切admin，開「人員與授權」，取消head_nurse對R001範圍。
2. head_nurse在原場重新查詢／開既有歷程，說出結果及下一步；不登入他人帳號。

觀察者預期：撤權後清單與歷程不再取得R001，R002仍依範圍；舊回應不可恢復內容。輪流登入只能驗證重登入後結果，既有工作階段部分須雙設定檔另驗，不冒稱都測到。這不是正式員工停權功能。
