# HITL治理是否容易理解

這是v0.3使用者理解觀察，沒有修改原HITL論文假設、評估指標、資料或結果。先問開放問題，再記原話；提示前後分開。畫面可展示的項目與紙卡討論分開，正確回答紙卡不表示功能已實作。

| ID／問題 | 可以直接展示的證據 | 僅能以卡片詢問的部分 | 提問與判讀依據 |
| --- | --- | --- | --- |
| H01 系統與人工差別 | U01系統固定待接手通知、U05人工回覆及作者。M1要求轉人工，不展示一般服務摘要；本場模型停用是主持人核對的新場設定，不另宣稱畫面有模型開關。 | 額外卡：「AI草稿建議安排某服務；尚未人工核准」；不啟用模型、不冒稱真實AI輸出。 | 「哪段是誰產生？可以直接當作完成或送出嗎？」可分辨系統固定通知、人工文字、假設草稿與未實際收件才正確。 |
| H02 現在誰負責 | U01接手前後、U04接受後的責任ID與歷程。 | 無有效責任人不等於現場無人照護。 | 先問、記ID再看歷程；看顯示名稱不能取代身分。 |
| H03 提交交班是否移轉 | U02交班待接受，原責任仍為nurse。 | 下班、通知或已讀是否足以轉移由U13比較。 | 說出指定接受才轉移；只看到已提出就說nurse2負責判錯。 |
| H04 過時交班 | U03新訊息後舊接受被拒或已失效而不提供接受鈕。 | U20例外核准後的競態尚未實作。 | 能指出需讀新資訊、由原有權人重提，不盲目重按或借帳號。 |
| H05 無有效責任人 | 主持人可在獨立開發者場次：nurse對R002接手→admin撤nurse的R002範圍→head_nurse查看「責任權限待確認」；不清除ownerID。 | 正式離職、停權、代理與例外接續用U10～U12，本輪現場U12保持紙卡。 | 「你找到什麼缺口？你現在能做什麼？」看到無效狀態不等於護理長可接手或已有人處理。展示設定與撤回由主持人，另記非U08的probe，不能改U編號。 |
| H06 權限與撤權 | U06～U08住民、角色、聯絡人隔離；舊內容清除。 | 正式職務變更、到期授權及生命週期。 | 拒絕是權限結果；不能以IT、其他人帳號或重新整理繞過。 |
| H07 失敗與斷線 | 已有錯誤提示可由主持人先在獨立測試場次停止本服務後刷新監控展示；保存錯誤畫面。 | U19以紙卡詢問「送出後無回執」，不能用讀取斷線證明真實LINE送出失敗／送達。 | 「現在知道什麼？還不能確定什麼？」結果未知不等於成功，不盲目重送；依院內備援承接。 |
| H08 額外工作與重工 | U01～U08記同資訊重填、切帳號、跨畫面、提示及耗時。 | U16比較行政／社工分流、原ERP與候選多一張表。 | 列具體欄位、次數與原因；不以開發者感覺推算省時。 |

每項理解判定：正確＝自行說出適用狀態及限制；部分＝只辨認一部分或理由不清；錯誤＝責任／送出／權限的核心判斷相反；未評估＝沒問、未展示或無足夠證據。以MEASUREMENT欄位記錄，不換算原研究治理分數，也不把個人誤解直接列程式缺陷。

可重現的開發者probe只證明展示素材可用。實際護理師／護理長能否理解，必須取得本人原話與行為後判讀；目前全部未執行。對H01的紙卡回答另標卡片，不稱已驗收AI草稿功能。
