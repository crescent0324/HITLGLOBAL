# 台灣長照資訊系統競品研究

研究 Jubo 智齡科技、CareOne、諾亞克 uCare，並逐項核對 HITLGLOBAL 的實際程式。本輪僅新增研究文件；以獨立分支提交，不合併 main，不修改應用、資料庫、既有測試或原 HITL 論文成果。

研究基準：2026-10-23。實際查閱及驗證：2026-10-24，台灣時間。無發布日期的現行網頁只能證明查閱日內容，無法保證完全回溯前一天。程式固定版本為 [`18729be4178e431418cbcbce010ca409f0b30fa9`](https://github.com/crescent0324/HITLGLOBAL/tree/18729be4178e431418cbcbce010ca409f0b30fa9)，提交前再核對遠端 main。[研究紀錄](RESEARCH_LOG.md)與[驗證紀錄](VALIDATION.md)保留方法及限制。

## 最終研究摘要

三家均有長照或護家照護與行政模組；HITLGLOBAL 現版的已測重點在本機觀察、授權、訊息案件、交班及生成治理。完整護理計畫、傷口／管路／給藥、人資薪資、會計及核銷仍有大幅差距，短期較適合與成熟系統整合。[功能矩陣](FUNCTION_MATRIX.md)、[程式差距](HITLGLOBAL_GAP_ANALYSIS.md)

| 產品 | 由本輪證據可支持的差異 | 必須保留的限制 |
| --- | --- | --- |
| Jubo | 三場域產品、行動交班、品質檢核；日照家屬 LINE、AI 聯絡簿；交班、個管及居督 AI；公開教學可補具體步驟 | 部分起價已公開，完整成本仍需報價；強制 AI 審閱、撤銷時序與接班責任規格未完全公開 |
| CareOne | 明列護家住民、護理、醫藥、人員、營養及財會；語音、動態表單、職務／住民群組與評鑑 | 現版護理師工作台、交班與主管 UI 未取得；歷史簡報僅索引可讀，價格與技術細節不足 |
| uCare | 住宿、居護、居服、日照；跨表單帶入、行政整合、品質、AI 語音及申報；居服步驟有第二來源 | TLCA 與其他 AI／白板不能混算；App 加密／刪除宣告有待釐清的範圍差異，現版完整操作仍不足 |
| HITLGLOBAL | 可讀程式及既有測試支持多聯絡人隔離、撤銷阻擋、指定接班確認與來源時間等控制 | 限本機與離線傳輸；真實 LINE、正式部署、臨床成效及全套 AI 有效性尚未驗收 |

競品差異依三份深度文件及來源登錄追溯。公開證據的細緻度不等於產品優劣；本研究沒有總分排名、獨立省時量測或獨家能力認定。

建議優先開發三項增量：

1. 真實 LINE 家屬授權與收件核對：將本機隔離與撤銷延伸到正式關係、事件重送及實際收件者。
2. 跨班人工案件責任與逾時追蹤：補足值班、代理、接收、時限與主管查核。
3. 照護來源追溯與草稿過時阻擋：經合法唯讀來源取得資料，核准與送出前各自重查版本、責任及授權。

這是尚待市場及場域驗證的建議，完整範圍、驗收與停止條件見[產品策略](PRODUCT_STRATEGY.md)。Jubo 已有來源、權限、簽核及專業人員主導的 AI 說明；競品未公開相同時序不能當成 H 的獨家優勢。

## 判讀規則與主要未確認事項

功能狀態只使用「已確認支援、已確認不支援、部分支援、規劃中、公開資料不足」。競品沒查到一律保留未知；H 的不支援只針對已核對的固定程式版本。A～D 另外表示實作與測試程度，不與支援狀態混用。

尚無公開證據足以確認的重點包括：三家完整現行權限矩陣、AI 強制審核及過時失效時序、多家屬撤銷、指定接班責任、正式第三方 API 契約、完整機構總價及多項備援目標。CareOne 現版 UI 是最大的介面缺口；uCare App 商店與產品說明的加密／刪除差異尚未排除。

合理公開途徑已涵蓋官網與功能頁、官方培訓、公開影片、App 商店、政府與標章頁、具名案例及大學簡報。需帳密、客戶代碼、未公開合約或廠商 Demo 的部分不繞過限制。所有不足逐列保留，作為後續取得授權或新資料時的更新佇列。

## 後續更新方法

先固定新程式 SHA 與查閱日，再按功能識別碼更新證據、場域及版本；新資料推翻既有判斷時，同步修改矩陣、缺口及個別深度文件，記錄理由。新增影片僅列入口時保留未播放標記；只有實際檢視後才改成已觀察。

需要比較現場便利性或採購時，使用相同角色、同題任務與明確資料分母，取得 Demo／合約後另做測量。本文可作可追溯的產品研究底稿；廠商宣稱不當成獨立實證，歷史教材不直接當現版佐證。
