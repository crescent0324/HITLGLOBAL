# 聯絡人對話隔離與配對撤銷

日期：2026-10-20（臺灣時間）。範圍為 HITLGLOBAL 本機體驗版；本輪未更動論文儲存庫、研究資料或封存核心。

## 修改原因

舊版以住民識別碼共用對話。家屬與住民本人詢問同一位住民時，訊息、模型脈絡及人工案件可能落在同一段對話。接通真實 LINE 前，須先拆開資料歸屬。

本版以「住民＋聯絡身分」建立不透明的對話識別碼。訊息、生成工作、人工狀態、處理進度及交班分別保存。住民照護紀錄與床位仍以住民識別碼管理；轉床不更動對話歸屬。

## 操作與控制

- 住民視窗新增「服務對話與回覆對象」選單；待辦直接開啟對應聯絡人的案件。
- 切換對話時，未保存訊息、回覆、草稿及進度先提示確認；取消切換會保留原對話及內容。
- 案件操作須提交 `conversation_id` 與 `case_id`。後端核對住民、對話、目前案件及操作者，過時案件操作回傳 409。
- 配對撤銷後拒絕新訊息、人工回覆及核准，並取消該對話尚未完成的生成工作。生成前後及送出邊界重新確認配對授權。
- 既有紀錄保留供有住民查看權限的院內人員處理；可依權限更新進度或結案。重新配對不會使已取消的工作復活。
- 目前僅允許離線傳輸。邏輯對話識別碼不能作為真實 LINE 收件者；誤將對話傳輸方式設為真實 LINE 時會拒絕送出。

## 舊資料處理

只新增 `contact_conversations` 資料表，不清空訊息或重設帳號。原有 `demo-care-住民識別碼` 對話保留為「院內測試／舊版紀錄」，沒有對外收件者；不推測過往混合訊息應分給哪位家屬。

開啟尚未有新資料表的既有環境時，先以 SQLite backup 建立兩個資料庫快照，並保存環境識別檔及備份 manifest；位置為 `runtime/backups/before-contact-conversations-…/`。備份不含 API 設定或工作階段金鑰。升級前應停止舊服務，兩個資料庫快照不提供跨程序持續寫入時的共同交易保證。還原須使用新目錄，勿覆蓋正在執行的資料庫。

## 實際驗證

在 Windows／Python 3.12.14 執行 `python -B -m unittest -v test_care_console`：47 項測試通過，耗時 110.161 秒。測試使用暫存資料庫、虛構帳號、離線傳輸與替代模型服務。

| 測試範圍 | 結果 |
| --- | --- |
| 同住民的家屬與本人、兩位家屬之訊息與模型脈絡分離 | 通過 |
| 人工回覆、結案、待辦及交班依對話分離 | 通過 |
| 跨住民對話、錯誤來源及過時案件識別碼遭拒 | 通過 |
| 撤銷配對阻擋回覆，既有紀錄可查看及結案 | 通過 |
| 生成期間撤銷配對，舊工作取消，重新配對不恢復舊工作 | 通過 |
| 舊版混合紀錄保留、新對話為空、升級前備份及重啟 | 通過 |
| 誤用真實 LINE 傳輸方式時拒絕邏輯對話識別碼送出 | 通過 |

瀏覽器另以獨立虛構環境確認：護理師切換家屬與住民對話、取消切換時保留未送出文字、家屬人工回覆不進入住民對話、管理者撤銷配對、撤銷後保留歷史且隱藏回覆、結案仍維持配對停用。照服員仍限授權住民範圍，沒有人工處理入口。

Python 語法、JavaScript 語法、Git 差異及提交內容另於上傳前檢查。首次匯入的 `IMPORT_MANIFEST.json` 與 `IMPORT_VERIFICATION.md` 保留為歷史紀錄，不代表本輪程式仍與匯入來源逐位元相同。

## 尚未涵蓋

本輪未驗證真實 LINE 身分、手機收件、Webhook 重送、正式模型回答品質、院內資料介接或多人跨程序部署。未進行護理師實際使用性研究或照護成效評估。原型的部分固定訊息仍沿用研究情境用語，正式試用前須依院方值班與服務流程調整。
