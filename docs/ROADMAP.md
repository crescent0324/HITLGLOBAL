# 護理之家試用規劃

此文件列出待辦與驗收目標，不表示功能已完成。初期目標是一家護理之家的受控試用。

## 1. 現場流程

由實際護理師與照服員確認家屬服務詢問、需護理師確認的問題、跨班交接三種流程，記錄目前操作步驟及資料來源。角色扮演不能替代此項工作。

驗收：有指定使用對象、值班責任、處理時限、逾時通知與斷線替代方式。

## 2. 聯絡身分與 LINE 收發

分開住民識別、床位、聯絡人、對話與實際收件者；由院方確認綁定、可揭露範圍及撤銷方式，再接通真實 LINE。

2026-10-20 已完成本機模擬聯絡人的對話、人工案件、生成工作與交班隔離，以及撤銷配對後的回覆阻擋；47 項自動化測試通過，詳見 [驗證紀錄](CONTACT_CONVERSATIONS.md)。真實 LINE 身分確認、Webhook 事件處理、實際收件者映射、傳送結果不明及重送控制仍待串接驗收。

驗收：不同聯絡人的對話不混用；換床不改變住民歸屬；解除授權後不得送出受限資訊；重複事件不造成重複處理；傳送失敗及結果不明可辨識。測試先使用虛構身分與已授權的測試帳號。

## 3. 員工帳號與職責

建立個人帳號生命週期、停權、密碼管理及工作階段控制，分開護理長與 IT 的權限。

驗收：後端逐次檢查角色與資料範圍；撤銷授權對既有工作階段生效；無權限者不能藉直接 API 存取資料。

## 4. 院內資料與服務內容

確認合法使用範圍、資料來源、住民識別、欄位單位、量測與同步時間、更正與衝突規則。建立機構服務資料的維護責任人及更新流程。

驗收：舊資料與同步失敗可辨識；未知值不補成正常；資料不足時進入可追蹤的人工流程；未完成的申請或預約不能顯示已完成。

## 5. 常駐與復原

設計 HTTPS 遠端入口、受保護登入、監控與通知、獨立執行資料、備份還原、版本更新及回復流程。不能直接移除本機限制並沿用示範密碼。

驗收：重啟後案件可恢復；備份可還原至新環境；服務故障有人收到通知；更新失敗能回復；預期使用量下測過多人操作與失敗情境。

## 6. 受控試用

院方同意資料與使用範圍後，由第一線實際完成工作，量測操作時間、漏接、誤送、重複登打及通知負擔。試用結果另行保存，不回填成論文原先的研究結果。

多機構資料隔離、導入訓練、維運服務條件、費用與離場資料匯出，於試用後依產品範圍安排。
