## 競品依據與範圍決策

本輪讀取研究分支固定提交 `f6ee97405421aa16f4081aefef9bab1556ef9378` 的 [PRODUCT_STRATEGY](https://github.com/crescent0324/HITLGLOBAL/blob/f6ee97405421aa16f4081aefef9bab1556ef9378/docs/competitive-research/PRODUCT_STRATEGY.md)、[HITLGLOBAL_GAP_ANALYSIS](https://github.com/crescent0324/HITLGLOBAL/blob/f6ee97405421aa16f4081aefef9bab1556ef9378/docs/competitive-research/HITLGLOBAL_GAP_ANALYSIS.md) 與 [FUNCTION_MATRIX](https://github.com/crescent0324/HITLGLOBAL/blob/f6ee97405421aa16f4081aefef9bab1556ef9378/docs/competitive-research/FUNCTION_MATRIX.md)。研究 PR 可獨立 Review；本程式分支不要求先合併研究 PR。

採用的方向是「家屬服務詢問的訊息責任與治理」。重用 `ConversationDirectory`、`ScopedLiveService`、`StaffWorkflow`、既有住民／授權、風險規則、案件與生成狀態。本機使用既有模擬身分入口，不新建家屬院內網頁帳號。

| 研究識別碼 | 決策 |
| --- | --- |
| F01／F03／F09／F10 | 保留模擬配對、聯絡人隔離與撤銷；真實身分、LINE 及 Webhook 不在本輪開通 |
| F12／F13／N04 | 以接手、進度、指定接受交班及結案完成一件詢問；補穩定責任 ID |
| C08／C09 | 住民照護權限與家屬對話權限分開；照服員可回報觀察，不能評估或處理家屬案件 |
| A05～A12 | 不修改既有風險、人工狀態與草稿失效機制；本輪不以離線展示冒稱完成 AI 內容品質驗收 |
| S06 | 護理長與 IT 仍是體驗版合併角色；正式角色分離列為開放真實使用前的條件 |

研究中 A 類只代表原固定版本的測試範圍。原 47 項測試沒有證明照服員的欄位最小揭露或同名帳號安全，本輪負向測試補足這兩個具體缺口，未改寫歷史研究快照。
