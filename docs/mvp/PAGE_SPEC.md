# 護理師工作台與主管案件監控：詳細頁面規格

> 版本說明：本文件保留 PR #2 的設計／驗證基準；2026-10-25 新增的護理長監控、IT 隔離、明確範圍與本輪測試，以 [監控工作台文件](../monitor/README.md) 為準。下列未實作狀態及 admin 描述屬當時版本，不能用來推定目前權限。

版本：MVP 0.1 設計，2026-10-25。下列明確標「現有」與「待實作」；現有本機畫面已用虛構資料操作，未實作的新頁面不當成已部署成果。

## 角色與工作單位

一個案件屬於一段「住民＋單一聯絡人」對話。住民、床位、聯絡身分、實際收件者與案件責任人分開。使用者開啟案件時，始終顯示住民識別、聯絡對象、案件編號及讀取時間。

| 角色 | 首頁與工作 | 寫入界線 |
| --- | --- | --- |
| 護理師 | 個人訊息待辦、交班給我、案件工作區、照護來源 | 接手後可處理；只能由目前責任 ID 寫入案件 |
| 護理長／臨床主管（目標角色） | 機構範圍監控、待接手、交班、逾期與品質查核 | 可以查看與追蹤，沒有無痕代回覆或強制移轉；代理／改派另設計並稽核 |
| admin（目前體驗） | 同時含臨床與 IT 管理能力 | 只供本機驗證；正式主管與 IT 角色尚未分離 |
| 照服員 | 自己工作範圍的照護觀察與回報 | 無家屬案件資料或處理入口；護理評估不能代填 |
| 家屬／住民 | 本輪以已配對身分模擬傳入訊息 | 沒有院內網頁登入；真實入口未接通 |

## P1：護理師工作台

現有頁面：`board`。可重用現有看板、待辦排序與開啟案件；目標是開班後先找到有責任要完成的訊息，不將數值或訊息風險當成臨床診斷。

```text
院內身分／最近成功同步時間／本機離線狀態
尚未接手 | 由我處理 | 交班給我 | 照護回報需確認
篩選列：全部未結案／尚未接手／由我處理／交班給我
案件列：住民＋床位 | 聯絡對象 | 原因與訊息摘要 | 責任與下一步
照護來源區：最近回報、上次評估、來源與時間
```

| 區塊 | 資料／互動 | 實作與驗收 |
| --- | --- | --- |
| 頁首 | 個人帳號顯示名稱、角色、最近成功同步；失敗保留舊資料並提示 | 現有；同步失敗不能更新成功時間或清空未保存內容 |
| 四張摘要卡 | 尚未接手、由我處理、交班給我、照護回報需確認 | 現有；前 3 項按案件，最後按住民，不能相加作總案件數 |
| 待辦篩選 | 全部、待接手、我的案件、交班給我 | 現有；`mine` 以帳號 ID，重名不誤判 |
| 排序 | 訊息風險高→中→低，同風險待接手優先，再按建立時間與案件 ID | 現有；是工作整理次序，急迫事件另走機構緊急程序 |
| 案件主列 | 案件 ID、住民、床位、聯絡人、配對有效性、原因、近期訊息、等待／持續時間、責任人、交班與下一步 | 現有；空白資料標未知，未接手不得顯示已受理 |
| 主要動作 | 查看並接手、繼續處理、查看交班、查看案件 | 現有；按鈕與後端權限一致；開啟時帶住民及對話，不只帶床位 |
| 照護來源 | 原始觀察、來源、觀察與入庫時間、上次已評估紀錄 | 現有；新的未評估資料不解除既有追蹤 |
| 搜尋／分頁／到期篩選 | 依案件 ID、住民、聯絡人、時間及機構範圍 | 待實作；目前看板不是大規模搜尋或分頁服務 |

空資料：顯示目前沒有符合篩選的待辦；不推論機構沒有問題。無權限：不發出受限資料、不顯示可用操作。載入失敗：保留上次資料、顯示讀取失敗，後端寫入仍重新驗權。手機／平板與長清單需另作裝置驗收，本輪只確認桌面本機流程。

## P2：單一案件工作區

現有：住民對話視窗的「服務對話／人工處理」。保留現有側重資訊與進度的結構；將來若改為獨立路由，仍須從後端重新查住民與對話權限。

| 區塊 | 必填／顯示與動作 | 控制及狀態 |
| --- | --- | --- |
| 身分帶 | 住民代碼、床位、聯絡人、案件 ID、資料讀取時間 | 聯絡人不可由自由文字決定；切換要處理未保存內容 |
| 案件狀態 | 待接手、已接手；責任名稱及穩定 ID；配對停用提示 | 現有。名稱只顯示；責任 ID 與登入帳號比對 |
| 原因與訊息 | 轉人工原因、相關分級、最近詢問、先前固定服務回覆 | 現有。分級說明可回查，與照護評估分開 |
| 接手 | 目前案件 ID；待接手時顯示 | 現有。成功才顯示責任取得；過時或已被接手，更新資料再確認 |
| 已處理內容 | 1～1000 字 | 現有。由責任人填寫；不是 AI 自動認定已完成 |
| 下一步 | 1～1000 字 | 現有。保存與提出交班必填 |
| 待確認事項 | 0～500 字 | 現有。可留白；有待外部確認時應寫具體對象及事項 |
| 保存進度 | 帶目前 revision | 現有。過時回應 409；保留本地文字，不自動覆寫別人的內容 |
| 交班 | 選指定接班帳號；先保存完整內容 | 現有。提出不移轉，接受時重核訊息版本；新訊息使舊交班不可接收 |
| 人工回覆 | 1～2000 字 | 現有本機功能。只在目前責任人且關係有效時可送出；實際 LINE 未接通 |
| AI 草稿 | 原文、來源、核准文字與審閱紀錄 | 現有部分底層／UI，完整生成審閱待驗證；本輪未啟用模型，不能列正式 MVP 已驗收 |
| 結案 | 1～1000 字處理結果 | 現有。只由責任人結案；保留歷史。結案不保證家屬已讀，也不替代臨床照護結束 |
| 歷史與稽核 | 進度、責任、結案、操作事件與時間 | 現有本機記錄。不是不可竄改封存；照服員不取得內容 |

核准草稿與回覆送出前須重查配對；配對撤銷時保留既有紀錄供有權護理人員處理，隱藏／拒絕對外回覆。重新配對不讓舊生成工作復活。

退出規則：切換住民、聯絡人、頁籤資料重載與關閉視窗，若涉及未保存內容則讓人員選擇保留或放棄。存檔成功才更新基準；網路錯誤不清空輸入。現有進度版本檢查保留，正式離線編輯佇列不在本輪。

## P3：主管案件監控

新增獨立監控頁與下列統計尚未實作。目前可用合併 admin 的既有未結案看板與案件歷史作本機預覽，不能稱為正式主管後台。

```text
臨床主管身分 | 機構／住民範圍 | 統計時間／資料更新時間
待接手 | 已接手 | 交班待接受 | 已設定時限的逾期
篩選：狀態／責任人／交班人／時間／風險／關係狀態
案件列表 → 唯讀案件軌跡／原始來源 → 有權處理者另行接手
遷移待確認及資料缺漏提示
```

| 元件 | 計算與互動規格 | 邊界 |
| --- | --- | --- |
| 統計範圍 | 所選機構與已授權住民，明示查詢時間及篩選條件 | 不用前端刪除不屬範圍的資料，後端先過濾 |
| 待接手 | 未結案且 status=pending | 沒有責任人；不能算已受理 |
| 已接手 | 未結案且 status=claimed、責任 ID 有效 | 有責任不表示已回覆；與傳輸狀態分開 |
| 交班待接受 | 有有效 pending handoff；與已接手數可能重疊 | 顯示原責任及指定對象；不能把重疊類別相加 |
| 逾期 | 未結案且明確 due_at 已過，使用伺服器時間 | due_at 尚未實作。未設定顯示「未設定」，不假造時限或逾期分母 |
| 清單 | 住民／聯絡人、狀態、責任 ID＋名稱、下一步、等待對象、建立／更新、到期、交班版本 | 預設摘要，點開有權範圍內的軌跡；不得預載全部家屬全文供前端篩選 |
| 搜尋與分頁 | 固定排序、限制每頁數量、游標綁定篩選 | 待實作；不得回傳其他機構或已失去權限的下一頁 |
| 結案追蹤 | 依期間查結案、處理結果與歷史責任 | 目前有單一對話最近 5 件結案；跨機構期間報表未實作 |
| 升級／代理 | 逾時提醒、代理及改派必須另訂責任、理由與確認 | 未實作。主管監控不自動授權代回覆或無痕改派 |
| 匯出 | 若有需要另訂欄位、用途、授權與稽核 | 未實作；不因能看頁面就預設可整批下載 |

主管主要行動是發現未接手或待確認案件、找出目前責任及下一步，依機構程序協調。正式 IT 角色不預設能讀家屬內容；現有合併角色須先拆分才可開放真實資料。

## P4：照服員照護頁

本輪已完成：只顯示工作範圍的照護住民、原始觀察與最近評估，可新增觀察，狀態固定尚未評估。顯示來源／時間／缺值；既有追蹤保留。家庭訊息及案件存在性也不透露。

若照服員需要向護理師通報，先使用現有照護回報與院內既有通報程序；將來要加入定向提醒，須另定任務、接收確認及責任，不能直接開放全部家屬對話作為替代。

## 共通錯誤與可用性驗收

| 情境 | 頁面行為 |
| --- | --- |
| 工作階段失效 401 | 回到登入，清除受限資料與未送出表單；不能讓下一個登入角色讀前一人的內容 |
| 權限不足 403 | 顯示權限錯誤，不重試或改用其他住民／對話，後端不寫入 |
| 案件或進度過時 409 | 保留輸入，提示更新；重新確認後才提交新版本 |
| 欄位錯誤 400 | 保留輸入並提示長度／必填／對話錯配，不能顯示成功 |
| 網路或服務失敗 | 保留內容與上次資料，明示結果未確認；不要盲目重送回覆 |
| 配對撤銷 | 仍可按權限讀歷史、保存進度與結案；回覆／核准遭拒 |
| 新訊息在交班期間抵達 | 明示交班過時；原責任人更新後重新提出 |

上述有既有本機實作與回歸覆蓋的部分見 [ACCEPTANCE](ACCEPTANCE.md)。新監控頁、到期與正式傳輸需另行開發及失敗驗收；本規格不把未測內容標為完成。
