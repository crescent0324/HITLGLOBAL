# 案件責任升級與代理處理規格草案

本文件只供機構確認下一階段需求。本輪未新增操作、API、角色權力、自動改派或通知服務。護理長維持授權住民範圍內的唯讀監控；IT 不取得案件內容；照服員不取得家屬服務案件。

## 目前能力與待確認界線

案件責任以穩定 `user_id` 記錄。一般交班須由目前有權護理師提出，指定接班護理師明確接受後才轉移責任；新訊息、進度與授權變更會使過時交班失效。監控可辨認責任帳號缺少有效護理師權限，尚無帳號停權、可工作狀態、代理資格與主管改派流程。

責任失效時保留原責任 ID、進度、交班及歷史證據。失效不代表新的人已接手，也不恢復自動回覆。不得將帳號更名當作換人接手。

## 需要涵蓋的情境

| 情境 | 建議的待確認處理流程 | 機構須決定的事項 |
| --- | --- | --- |
| 護理師離職、停權或失去住民授權 | 停止該帳號後續案件操作，標示責任權限待確認；保存原責任與失效原因。既有待接受交班重新驗證，不能沿用過期資格。 | 停權資料來源、離職生效程序、誰能確認暫存責任及補接手。 |
| 責任人突然無法工作 | 有權人員提出代理需求，記錄提出者與原因；候選代理仍須有該住民的護理師權限。 | 誰可申報、如何證明、代理起訖及撤回程序。 |
| 指定接班者未接收 | 原責任維持至有效接收或機構核准的例外程序完成；監控清楚顯示尚未接受。 | 未接收的確認方式、聯繫順序、何時進入例外程序。 |
| 護理長發現無有效責任人 | 唯讀頁呈現待確認狀態與原因；依機構程序提出處理需求。 | 護理長能否提出改派建議、向誰提出、誰負責實際完成。 |
| 有權人員重新接手或主管提出改派 | 一般接手核對候選人的角色、住民授權、現有責任、案件與交班版本。主管提案與實際核准、接收分別記錄。 | 是否允許例外改派、核准角色、是否須雙人核准，以及新責任人的確認方式。 |
| 每次改派的理由、授權與稽核 | 記錄案件 ID、原與新責任 ID、提出與核准及接收者、理由、依據、版本、時間與結果。失敗及取消也須留紀錄。 | 理由分類、證據權限、保留政策、稽核查閱角色。 |
| 主管無法處理 | 提供經機構確認的替代聯絡流程；記錄實際聯繫與受理結果。系統不自行宣稱已通知、已送達或已有人接手。 | 值班代理、替代主管、既有院內通報管道、休假及無回應時的順序。 |

## 建議的狀態與操作邊界

可另設「責任權限待確認」「代理需求待核准」「改派待接收」「已取消」等協作狀態，與原本 pending／claimed／closed 分開。這些狀態不改變 HITL 治理狀態、草稿審閱或送出資格。機構核准前，名稱與轉移規則均屬提案。

未來若實作提案 API，送出與接受都須重新核對當下角色、住民授權、案件 ID、原責任 ID、案件資料版本及提案版本，採同一交易轉移責任並追加稽核事件。兩人同時接手只允許一個成功；另一個回報衝突並重新載入。撤權、案件已結案、候選人失格、內容變更及撤銷提案均須阻擋過時接受。

「主管提出改派」不能直接等同「主管有無條件改派權」。必須先確認核准與接收規則，再決定是否新增細分能力；既有護理長唯讀角色不得透過通用管理端點繞過限制。IT 只提供帳號與授權維護，不得因此讀取改派理由中的臨床內容。

## 上線前必須取得的 SOP

機構需確認各班別負責人、代理資格、授權與核准矩陣、未接收及無責任人的聯繫程序、例外改派條件、交接完成認定、故障時紙本或電話流程，以及紀錄保存與稽核查閱規則。

本草案沒有設定案件處理時限、醫療急迫標準、逾期門檻、自動升級倒數、無條件主管改派權或自動聯繫對象。畫面可顯示已經過的時間；時間長短本身不能推定醫療急迫性。

## 後續驗收條件

- 有權護理師才可接受，且每次接受都使用最新資格與版本。
- 原責任人失效後的留存、提出需求、核准及接收可逐一稽核；不偽造離職或無法工作的原因。
- 同名、帳號更名、同時接手、提案取消、新訊息、進度變更、撤權、停權與結案均有衝突測試。
- 護理長、IT、照服員、跨住民與既有工作階段的越權測試繼續通過。
- 未取得通知回執時只記錄嘗試結果；替代通報失敗須可辨識，不能直接標為已受理。
- 機構核准 SOP 與權限矩陣後才另開實作任務。
