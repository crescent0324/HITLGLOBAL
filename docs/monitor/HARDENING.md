# 監控穩定性修正與驗證

基準：2026-10-25 已合併 PR #3 的 main `2d23e85ad76bfe87644f8e5926f6b3ccbfacfbae`。獨立分支：`fix/monitor-refresh-pagination-backup-20261025`。原 PR #3 的 GitHub review、review thread 與 comments 查詢未取得內容；本輪依使用者明列的 A～E 要求重現與驗證，不宣稱已逐條回覆未取得的 Review 原文。

## 差異與實際行為

| 項目 | 原行為 | 本輪修改 |
| --- | --- | --- |
| 手動篩選與背景更新 | loading=true 時直接丟棄新查詢，全域 busy 也擋住連續提交。 | 手動查詢捕捉篩選與請求 ID，取代舊 GET；AbortController 取消傳輸，ID、工作階段版本與角色檢查阻擋晚到內容及舊 401 副作用。讀取不佔用寫入操作鎖。 |
| 初次登入載入 | 登入流程等待監控 GET，延遲時登出也被 busy 阻擋。 | 身分確認完成後獨立啟動監控讀取，載入中仍可登出。 |
| 篩選草稿、錯誤與輪詢 | 回應重建責任人選單會改掉未提交的值；輪詢會清掉錯誤。 | 保留目前選單草稿；有清單請求、未套用篩選或未解決錯誤時不另發輪詢。手動查詢可繼續。 |
| 游標失效 | 409 只清畫面，要求使用者重整。 | 帶游標的 409 以原已套用條件重新讀第一頁一次；成功顯示指定訊息。清單與歷程皆取代舊頁；第二次失敗停止。 |
| 403／404 | 角色重查可能重啟相同失敗查詢；單案失權未必讓較舊清單失效。 | 403 重新核對工作階段；角色相同時保留錯誤，角色改變才切換。單案 404 清除內容並使進行中的舊清單失效。 |
| 查詢與版本 | 全量列及 DTO 累積於 Python，逐案最新訊息缺少索引。 | SQL 聚合／GROUP BY、單頁 DTO、索引及逐列雜湊。完整版本欄位維持原樣，清單在同一讀取交易內取得版本、統計與頁面。 |
| 備份 | 含密碼雜湊卻標成不含憑證；失敗可能留下成功名稱的殘檔。 | format_version=2 的敏感性欄位、完整性與雜湊、同檔案系統完成後更名；失敗以 .incomplete-* 保留，不改寫舊備份。 |

API 回應欄位、簽章游標、900 秒期限與授權 SQL 邊界不變。護理長仍唯讀、IT 無臨床內容、照服員無家屬案件；接手、交班接受與穩定責任 ID 規則不變。`care_console/core/` 及研究封存檔案未修改。

## 先重現再修正

原版執行 13 個前端情境，8 個失敗、5 個通過：新篩選被略過、三次提交被阻擋、錯誤被輪詢清除、責任人草稿被覆寫、撤權後新查詢未發出、舊 401 副作用及兩個 409 回復情境。JSDOM 設為可見頁面，測試刻意忽略 abort，確保保護不只依賴取消成功。

備份原版五個測試中三個斷言失敗、一個缺少 manifest 欄位錯誤；另有一個損壞來源檢查通過。後續再加入同角色 403 不重查、歷程 409 取代、404 舊清單失效與初次登入載入中登出，將新發現的缺陷先留下失敗紀錄。

## 自動驗證

原有 77 個 Python 測試完整保留。新增備份、索引、版本雜湊一致性、游標自然過期與各類資料變動測試；最終結果及原始輸出隨交付報告保存。前端測試執行實際 app.js 與 index.html，模擬可控制順序的 fetch，涵蓋背景與手動查詢、快速三次篩選、逆序完成、登出、IT 切換、撤權、重複輪詢、400／401／403／404／409／500 與網路錯誤。

本輪完整 Python 測試共 90 項通過（232.330 秒，原有 77＋新增 13）；獨立 Review 後前端增加至 21 項，全數通過（1.870 秒）。新增歷程錯誤保留、歷程載入輪詢去重及第二次 409 停止重查。原測試檔未刪除或修改。獨立 Review 的發現、修正與複驗另記於 REVIEW.md。

原 OpenAPI 3.1 契約經 validator 及 13 組實際回應 schema 再驗證（2 個 GET、15 個 schema），沒有新增權限或回應欄位。效能原始紀錄、方法、查詢計畫及記憶體見 [PERFORMANCE.md](PERFORMANCE.md)。備份失敗、敏感內容、還原與正式維運設計見 [MIGRATION.md](MIGRATION.md)。

## 實際瀏覽器驗收

使用獨立 localhost 虛構資料目錄與離線 Provider，透過測試伺服器在應用產生回應後延遲傳回，以便重現已取得舊授權資料的晚到回應。操作由實際瀏覽器進行，未從頁面注入 appState 或呼叫內部函式。JSDOM 測試與瀏覽器證據分開記錄。

已確認延遲請求期間連續三次篩選後仍顯示最新結果；新案件使游標 409 後會保留篩選回第一頁；撤銷 R001 後舊回應不恢復 R001；登出並登入 IT 後監控及歷程維持空白；初次登入讀取延遲時仍能登出。其餘錯誤與草稿結果記錄在交付的 browser-qa.json 與截圖。

共保存 12 個實際瀏覽器情境，另包含真正 15 秒輪詢延遲時由手動查詢取代、403 保留草稿、500 與停止伺服器造成的斷線、恢復連線後的空資料，以及 Review 修正後歷程 500 跨輪詢持續顯示。最後一個歷程錯誤後的伺服器記錄沒有新增清單或歷程請求；測試服務與暫存瀏覽器分頁已關閉。

## 剩餘限制與下一階段

- 指紋仍需掃描授權案件；本輪改善記憶體與最新訊息查詢成本，沒有宣稱任意資料量皆為固定耗時。
- 目前單機服務鎖、SQLite 讀取交易及每次 API 驗證不等同跨程序或分散式撤權推播；外部授權變更需下一個有效查詢才能反映。
- AbortController 無法保證服務端立即停止運算，因此仍以 ID 與工作階段版本為判準。
- 備份仍含敏感資料及密碼雜湊，未加密。需機構確認 OS 權限、金鑰管理、保存與還原 SOP，沒有新增雲端備份或自動刪除。
- [NEXT_PHASE.md](NEXT_PHASE.md) 只提出責任升級及代理處理草案。未授予主管無條件改派權，沒有自訂醫療急迫標準或處理時限。
- 第二輪獨立 Review 的範圍、發現與處置另列 [REVIEW.md](REVIEW.md)。Review 完成不構成正式機構資安或現場使用性驗收。
