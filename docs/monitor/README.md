# 護理長案件監控工作台

2026-10-25，本機虛構資料版本。基準為已合併 PR #2 的 main `e7f319973806c89fc49eb3be0e1c59dc4cbf6034`。本輪沿用原有接手、進度、指定接受交班、回覆及結案，新增護理長唯讀監控及 IT 職責隔離。原論文程式與實驗結果沒有修改。

## 已完成的行為

| 角色／體驗帳號 | 預設範圍 | 本輪行為 |
| --- | --- | --- |
| 護理師 nurse、nurse2 | 六位住民的明確授權，可撤銷 | 原照護與家屬案件處理；依責任 ID 寫入，不可讀主管監控 API |
| 護理長 head_nurse | R001、R002 的明確授權，可撤銷 | 唯讀查案件、責任、下一步、交班及逐次進度歷程；不能接手、代回覆、結案、改派或擴充自己的權限 |
| 照服員 caregiver | R001、R002 | 只讀照護紀錄並回報未評估觀察；無監控、家屬訊息或案件操作 |
| IT admin | 沒有臨床住民範圍 | 管理工作範圍與模擬聯絡人關係；不能讀照護、家屬對話、案件、監控或下載完整資料庫 |
| 家屬／住民模擬身分 | 沿用既有配對 | 不具院內網頁登入權限；仍未接通真實 LINE |

體驗密碼沿用 localhost 示範密碼。這是可驗證的應用程式角色隔離，並非已完成正式員工帳號、密碼管理或機構資安驗收。

監控頁依目前授權先查後端資料，提供狀態、責任帳號及建立時間篩選，按案件 ID 由新到舊排列。每頁 1～50 件，預設 10 件；歷程預設 20 件，可讀較早事件。分頁游標簽章綁定查看帳號、授權範圍、篩選及資料版本，有效 15 分鐘；資料或權限更新時須從第一頁重查。

看板不預載家屬原文。歷程提供案件事件、進度快照、交班與處理結果，也不提供完整對話原文。所列人工進度可能含照護內容，仍只有獲授權護理長可讀；IT 管理入口不會收到這些欄位。

## 統計與時限

`open_cases = pending_cases + claimed_cases`。交班待接受是已接手案件的子集合，兩者不相加。有效交班須符合目前責任 ID、雙方護理師角色與住民授權、原訊息版本；不符者另顯示須重新確認，原責任不自動移轉。已失去授權的責任帳號會標示「權限待確認」，不由監控頁自動改派。

`due_at` 新欄位預設 NULL，沒有設定端點、預設時限或自動通知。未設定顯示「未設定」，`overdue`／`overdue_cases` 為 null，不能把未知當成沒有逾期。如果資料中已有未經本版核可的期限，標為待機構確認，仍不判定逾期。

## 重跑與展示

在 `care_console/` 使用既有 requirements：

```powershell
python -B -m unittest -v test_care_console test_case_monitor
python -B demo_monitor.py --output monitor-demo.json
```

展示程式只接受全新虛構目錄，CLI 自建暫存資料並在結束後清除。包含護理師建立及交班、護理長查閱、照服員觀察、指定接班者回覆結案、IT 拒絕、撤權及重啟；不讀既有 runtime，不連真實 LINE 或模型。
